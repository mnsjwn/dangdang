# 당당

> 밥 먹고 졸리지 않는 오후

먹은 음식만 입력하면 **식후 졸음 위험**을 계산하고,
졸리지 않으려면 **지금 몇 분 움직여야 하는지** 알려주는 웹앱입니다.

SDG 3 (건강과 복지) · 대전 지역사회 문제해결 프로젝트

---

## 왜 만들었나

- 국내 19~39세 청년 중 **약 300만 명이 당뇨병 전단계** (청년 5명 중 1명꼴)
  — [대한당뇨병학회 당뇨병 팩트시트 2024](https://diabetes.or.kr/bbs/download.php?code=fact_sheet&number=2960)
- 19세 이상 성인 **21.5%가 대사증후군** (국민건강영양조사 9기)
- **식후 10~15분 걷기만으로 하루 혈당곡선 면적이 12~22% 감소**한다는 연구가 이미 있음

"밥 먹고 걸으면 좋다"는 다들 알지만,
**내가 방금 먹은 메뉴가 정확히 얼마나 위험하고, 몇 분을 걸어야 하는지**는 아무도 모릅니다.
당당은 그 숫자를 계산해 줍니다.

> 학술적으로는 **식후 고혈당(postprandial hyperglycemia)** 이지만,
> 사용자가 실제로 체감하는 증상인 "식후 졸음"을 화면 언어로 씁니다.

## 기능

| 화면 | 내용 |
|---|---|
| 온보딩 | 6단계로 사용법 안내 |
| 로그인 / 회원가입 | 닉네임 + 비밀번호, 신체정보(몸무게·키·나이) 입력 |
| 음식 입력 | 음식 검색 → 인분 ± 조절, **미등록 음식은 종류 추정 후 카테고리 평균 적용** |
| 결과 | 총 혈당부하(GL) 게이지 + 졸음 위험 등급 + 권장 활동 시간 |
| 활동 선택 | 걷기 / 계단오르기 중 선택 (예상 감소율·칼로리 표시) |
| 타이머 | 원형 카운트다운, 실시간 소모 칼로리 |
| 완료 | 날짜 도장 지급 → 구글 시트에 기록 |
| 마이페이지 | 도장 달력 · 실천일수 · 최근 7일 졸음 위험 차트 |
| 가까운 산책로 | 카카오 지도에 대전 서구 공원 표시, 거리·도보 시간 + 실제 길 안내 연결 |

## 계산 방식 (전부 결정적 공식 · AI 미사용)

```
혈당부하(GL) = GI × 탄수화물(g) ÷ 100          ← 한 끼는 항목별 GL의 합

졸음 위험 등급   GL < 20  낮아요
                GL < 40  보통이에요
                GL ≥ 40  높아요

권장 걷기 시간   GL ≥ 55 → 20분 / GL ≥ 30 → 15분 / 그 외 10분

예상 감소율(%)  = min(32, 분 × (MET ÷ 3.5) × 1.2)
소모 칼로리     = MET × 체중(kg) × 시간(h)

MET : 걷기 3.5 · 계단오르기 8.0
```

딥러닝·LLM을 쓰지 않습니다. 미등록 음식의 종류 추정도 **키워드 규칙**입니다.

## 데이터 출처

세 층으로 나뉘며, 각 항목의 `giSource` / `carbSource` 필드에 어디서 왔는지 기록돼 있습니다.

**① 혈당지수(GI) — 학술 논문**
> 송수진·최하늬·이사야·박정민·김보라·백희영·송윤주.
> 「한국인 상용 식품의 혈당지수(Glycemic Index) 추정치를 활용한 한국 성인의 식사혈당지수 산출」.
> 한국영양학회지(Korean J Nutr) 2012;45(1):80-93.
> [전문 PDF](https://synapse.koreamed.org/pdf/10.4163/kjn.2012.45.1.80)

국민건강영양조사 식품코드 653개에 GI를 설정한 논문이며, 부록의 209개 값 중
대학생 일상 식단에 해당하는 항목을 추려 `data/gi-table-2012.json`에 담았습니다.
각 음식에 논문의 식품코드(`giCode`)를 남겨 두었습니다.

논문에 단독 항목이 없는 복합요리(김밥·떡볶이·비빔밥 등)는 주재료의 GI를 적용하고
`giBasedOn`에 근거를 표기했습니다. (예: 김밥 → 밥(1197), 떡볶이 → 가래떡(1211))

**② 탄수화물 — 공공데이터**
> 식품의약품안전처 [전국통합식품영양성분정보 표준데이터](https://www.data.go.kr/data/15100070/standard.do)
> (음식 / 가공식품 / 원재료성식품, 총 73,199행)

같은 대표식품명에 속한 제품들의 **100g당 탄수화물 중앙값**을 구한 뒤 1인분 중량을 곱해 환산합니다.

**③ 공원·산책로 — 공공데이터**
> 행정안전부 [도시공원정보 표준데이터](https://www.data.go.kr/data/15012890/standard.do) (대전광역시 서구)

실제 위도·경도를 이용해 **하버사인 공식**으로 현재 위치와의 직선거리를 계산하고,
카카오 지도 위에 표시합니다. "길 안내"는 카카오맵의 실제 도보 경로로 연결됩니다.

> 대전 서구 112곳 중 86곳이 1,500㎡ 안팎의 어린이공원이라, 걸을 공간이 있는 유형
> (근린·체육·수변·문화·소공원)이거나 1ha 이상인 **25곳**만 안내 대상으로 씁니다.
> 원본 데이터의 명백한 오류(어린이공원 면적 399ha)도 함께 걸러냅니다.

> **1인분 중량은 앱이 정한 기준**이며, 각 항목의 `serving`에 g으로 함께 표기합니다.
> (예: `라면 1봉지(120g)`) 식약처 값이 조리 전(건면·분말) 기준인 항목은
> 조리 전 중량을 곱하고 라벨에 기준을 밝힙니다. (예: `국수 1인분(건면 100g)`)

## 기술 스택

- **프론트엔드** React 18 + Vite
- **음식/공원 DB** 정적 JSON 번들 (앱에 내장 — 실행 중 외부 API 호출 없음)
- **사용자/기록 저장** Google Sheets + Google Apps Script
- **지도** 카카오 지도 JavaScript SDK
- **알림** [sonner](https://github.com/emilkowalski/sonner)
- **배포** 정적 호스팅

외부 API를 실행 시점에 호출하지 않으므로 네트워크가 끊겨도 계산 기능은 그대로 동작합니다.

## 실행

```bash
npm install
npm run dev
```

기록 저장 기능을 쓰려면 프로젝트 루트에 `.env` 파일이 필요합니다.

```
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/...../exec
```

지도는 카카오 JavaScript 키를 쓰며 기본값이 코드에 들어 있어 별도 설정 없이 동작합니다.
(등록된 도메인에서만 쓸 수 있는 공개용 키라 저장소에 포함해도 됩니다.
바꾸려면 `VITE_KAKAO_JS_KEY`를 지정하세요.)

Apps Script URL 발급 방법은 [`backend/README.md`](backend/README.md)를 참고하세요.
(구글 시트 생성 → Apps Script 배포까지 단계별로 정리돼 있고,
`backend/당당_시트템플릿.xlsx`를 드라이브에 올리면 시트 구조가 그대로 만들어집니다.)

## 데이터 다시 만들기

공공데이터 원본 CSV는 용량이 커서 저장소에 포함하지 않았습니다.
[`data/raw/README.md`](data/raw/README.md)의 안내대로 CSV를 내려받아 `data/raw/`에 넣고:

```bash
node scripts/build-data.mjs
```

`data/foodDB.json`과 `data/parks.json`이 다시 생성됩니다.
